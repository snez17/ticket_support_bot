# ML/LLM в системе

## Задачи и подходы

| Задача | Решение | Почему |
|--------|---------|--------|
| **Классификация** (тема, риск) | Правила + DistilBERT | Правила — быстро, ML — точнее |
| **Поиск в базе знаний** | SentenceTransformers + FAISS | Эмбеддинги ищут по смыслу |
| **Генерация ответа** | Ollama (qwen2.5:3b) | Переформулирует контекст в ответ |
| **Дедупликация** | Косинусное сходство | Сравнивает эмбеддинги |

---

## Где что используется

| Инструмент | Задача |
|------------|--------|
| **Правила** | Детект PII, платежей (быстро, безопасно) |
| **DistilBERT** | Классификация темы/риска (в проде) |
| **SentenceTransformers** | Эмбеддинги для RAG |
| **FAISS** | Быстрый поиск в базе |
| **Ollama (LLM)** | Генерация ответа из контекста |

---

## Где LLM НЕ стоит использовать

- **Горячий путь** (классификация) — слишком медленно
- **Детект PII** — лучше правил/регексов
- **Дедупликация** — дешевле через эмбеддинги

---

## Baseline (что запускать первыми)

1. **Правила** → быстро, понятно, безопасно
2. **DistilBERT** → лёгкий, быстрый, можно на CPU
3. **RAG + LLM** → качество, но дороже

---

## Метрики качества

| Модель | Метрика | Цель |
|--------|---------|------|
| Классификатор | F1, Precision, Recall | > 0.90 |
| RAG поиск | Recall@3 | > 0.85 |
| LLM ответ | BERTScore, ROUGE | > 0.80 |

---

## Низкая уверенность

- Порог: **confidence < 0.5**
- Действие: **эскалация оператору**
- Двойная страховка: и правила, и уверенность

---

## Откуда берутся модели

| Модель | Откуда | Данные |
|--------|--------|--------|
| **DistilBERT** | Hugging Face | Fine-tune на 15K размеченных тикетов |
| **SentenceTransformers** | Hugging Face (готовый) | Без дообучения |
| **qwen2.5:3b** | Ollama (готовый) | Без дообучения |

---

## Разметка данных

- **Объём:** 15 000 исторических тикетов
- **Что размечают:** тема, риск, качество ответа
- **Кто:** 3 аннотатора
- **Срок:** 2–3 недели
- **Контроль:** 20% выборки перепроверяется
